Admin Testing Panel — Blockchain Attack Simulation Admin Only

Testing

This panel lets an admin simulate three classic blockchain attacks to verify that the Validate Blockchain tool (above) correctly detects them. Each test takes a snapshot of the chain before the attack so you can Restore Chain afterward and run another test. After running an attack, click Validate Blockchain (above) to see the validator catch it.

Test 1 · Block Tampering Hash Integrity

Modifies the voter ID inside an existing block's transaction. The block's stored hash no longer matches the (tampered) contents - the validator's recomputedHash check should fail.

Test 2 · Unauthorized Transaction Signature Verification

Mines a new block containing a transaction whose declared transactionHash does NOT match the hash of the actual payload - simulating a forged vote under another student's identity. The validator's signature check should fail.

Test 3 · Direct Chain Injection Consensus Bypass

Pushes a fake block directly onto the chain array without going through the mining process. The fake block has an invalid PoW hash (doesn't start with "000") and/or a broken previousHash linkage. The validator should catch it.

Mock Student Information System (SIS) — SQL Backend Admin Only

SQL + JS

The Mock SIS is backed by both a real MySQL-compatible SQL schema (sql/schema.sql + sql/seed.sql) and an in-memory JavaScript mirror (js/sis-data.js) so the system runs entirely client-side on GitHub Pages while still being governed by a proper SQL schema. Both files contain the same 220 synthetic student records. In a production deployment you would replace the JS shim with a fetch() call to a Node + Express + MySQL backend that runs the same SQL queries shown below.
